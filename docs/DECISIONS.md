# Decisions made without asking

| ID   | Decision                                                                                                                                                                                                                                                                                                                                                                                                                         | Rationale                                                                                                                                                                        |
| ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| BD1  | Root `LICENSE` (MIT, pre-existing) was first left untouched. The owner then decided to replace it with a short per-package notice (Apache-2.0 for core, mcp, cli; proprietary for everything else). The notice still needs a legal re-read.                                                                                                                                                                                      | Changing the repository licence is the owner's call; the MIT text contradicted rule 5.                                                                                           |
| BD2  | TypeScript sources are consumed directly across workspace packages via `tsconfig` paths and vitest aliases; `tsup` builds exist for publishing.                                                                                                                                                                                                                                                                                  | Fast iteration, no build step before tests.                                                                                                                                      |
| BD3  | Test database: PGlite (real Postgres semantics incl. row-level security, in-process).                                                                                                                                                                                                                                                                                                                                            | Lets schema, migrations and RLS be tested without a server.                                                                                                                      |
| BD4  | HTTP framework for API: Hono. Validation: zod.                                                                                                                                                                                                                                                                                                                                                                                   | Small, typed, runs on node http.                                                                                                                                                 |
| BD5  | Chain module layout: `packages/chain/src/tatum.ts` is the single gateway; transports live in `packages/chain/src/tatum/`.                                                                                                                                                                                                                                                                                                        | Honours "single gateway file" while keeping transports testable.                                                                                                                 |
| BD6  | Package name scope `@buiry/*`; CLI binary `buiry`.                                                                                                                                                                                                                                                                                                                                                                               | Matches architecture proposals.                                                                                                                                                  |
| BD7  | Initial confidence/decay/weights use architecture section 9 values verbatim and are exposed as `LearningConfig`.                                                                                                                                                                                                                                                                                                                 | Tunable defaults.                                                                                                                                                                |
| BD8  | Token estimator: ceil(chars / 4) for prose.                                                                                                                                                                                                                                                                                                                                                                                      | Deterministic, no tokenizer dependency.                                                                                                                                          |
| BD9  | Auto-promotion counts only helpful reports from sessions other than the creating session (no self-promotion); agent `outdated` reports are treated like `wrong`.                                                                                                                                                                                                                                                                 | Anti-gaming rule in architecture section 9; `outdated` is in the tool schema but not the score table.                                                                            |
| BD10 | `main` is protected for merges and confirmed direct writes by non-admins, but agents may write `proposed` memories to it (project setting `allowProposedOnMain`, default true).                                                                                                                                                                                                                                                  | Without this the single-branch demo and solo flow cannot work; FR-H1 intent is preserved because proposed memories are low-trust and merges still need an admin.                 |
| BD11 | Agent tokens can carry a `confirm` scope; such an agent may confirm other agents' memories but never its own. Default agents cannot confirm.                                                                                                                                                                                                                                                                                     | PRD FR-G1 lists a confirm permission; D17 and the anti-gaming rules forbid self-promotion.                                                                                       |
| BD12 | Error code `invalid_input` and `plan_limit` were added to the stable list from architecture section 10.                                                                                                                                                                                                                                                                                                                          | Validation and plan errors need codes.                                                                                                                                           |
| BD13 | Two idempotency layers: a request-level key (project, branch, type, text, evidence, agent) deduplicates replayed tool calls; the storage-level key (namespace + header + text) deduplicates writes.                                                                                                                                                                                                                              | The header contains a fresh memory id, so the architecture's storage key alone cannot catch a reconnect replay of the same call.                                                 |
| BD14 | Agent REST surface for the MCP server lives under `/v1/agent/*` (project implied by the token).                                                                                                                                                                                                                                                                                                                                  | The documented `/projects/{id}/...` routes are for people and API tokens.                                                                                                        |
| BD15 | Chain gateway endpoints (`TATUM_GRPC_ENDPOINT`, `TATUM_JSONRPC_URL`) are env vars with no defaults.                                                                                                                                                                                                                                                                                                                              | Rule 3: no invented hostnames.                                                                                                                                                   |
| BD16 | The write queue table is visible to tenant roles only through a project they own (row-level policy on `project_id`).                                                                                                                                                                                                                                                                                                             | write_jobs has no workspace column and is touched inside tenant transactions.                                                                                                    |
| BD17 | Write queue completion maps back through a `ref` (the memory event id) on the job.                                                                                                                                                                                                                                                                                                                                               | Lets the worker set blob ids on events and memories without the storage package knowing about memories.                                                                          |
| BD18 | Tenant isolation has three layers: (1) the token or session fixes the tenant and project, request fields never name one; (2) every lookup is scoped by project and answers `not_found` for other tenants' ids; (3) row-level security under an unprivileged role. The isolation suite enumerates the route registry so a new route cannot skip it.                                                                               | Architecture section 5, NFR-6.                                                                                                                                                   |
| BD19 | Dashboard sessions: opaque `bry_ses_` tokens (keyed hash stored), HttpOnly SameSite=Lax cookie, Origin check on cookie-authenticated writes; bearer sessions are also accepted for the CLI. Email-link sign-in links an account only with Google or another email sign-in of the same verified address; wallet and GitHub identities never merge silently.                                                                       | Account-takeover safety; PRD FR-A1, FR-A5.                                                                                                                                       |
| BD20 | The live feed polls the activity table by a monotonic sequence number (SSE), not by timestamp.                                                                                                                                                                                                                                                                                                                                   | Same-millisecond rows with random ids were skipped when ordering by timestamp and id.                                                                                            |
| BD21 | Entitlements are placeholders (free / pro / team limits are not prices) and can be disabled with `BUIRY_ENTITLEMENTS=off` for self-hosting.                                                                                                                                                                                                                                                                                      | PRD V10: prices and limits are open.                                                                                                                                             |
| BD22 | Webhook signing secrets are stored encrypted (AES-256-GCM keyed from `BUIRY_SECRET_KEY`) because the server must sign with them; agent and API tokens are stored only as keyed hashes.                                                                                                                                                                                                                                           | Different threat: signing needs the secret, authentication does not.                                                                                                             |
| BD23 | Dashboard (`apps/dashboard`): Vite + React + TypeScript single-page app, hand-written CSS driven by the spec's design tokens (dark first, light supported), Inter and JetBrains Mono from fontsource, lucide icons, react-router. No UI framework.                                                                                                                                                                               | Small bundle, tokens stay the single source of colour, no dependency on a design-system package.                                                                                 |
| BD24 | The dashboard talks only to the public REST API (`/v1`). Sessions are the HttpOnly cookie; a pasted bearer session token is also accepted and kept in localStorage. In development Vite proxies `/v1` so the cookie is same-origin; in production the API serves `apps/dashboard/dist` (`DASHBOARD_DIR`, SPA fallback, hashed assets immutable).                                                                                 | Same origin avoids CORS and keeps the Origin check on cookie writes meaningful.                                                                                                  |
| BD25 | Live updates use the existing activity SSE stream, read with `fetch` (not `EventSource`) so a bearer token works; events trigger debounced reloads of the visible queries and drive the live indicator (connected, reconnecting, off).                                                                                                                                                                                           | `EventSource` cannot send an Authorization header.                                                                                                                               |
| BD26 | Spec screens that need data or endpoints the service does not have are built with an honest placeholder rather than invented data: bulk move-to-branch and flag notes, memory renewal, billing payment methods, browser wallet connect, the marketing site and the internal admin console. Each says what is missing in the UI.                                                                                                  | Rule: never fake behaviour; log it in `docs/ASSUMPTIONS.md` where a third party is involved.                                                                                     |
| BD27 | Per-project memory-rule settings (auto-promotion, half-lives, review threshold) are applied by the service through `learningFor` (project settings overlaid on the service default; invalid values ignored). The default token budget and public-showcase settings are stored and used by their own features.                                                                                                                    | Overrides live in the service layer; the pure core stays unchanged.                                                                                                              |
| BD28 | The development server (`pnpm dev:api`) runs the real API and MCP endpoint over the mock relayer and mock Tatum, seeded with the spec's sample project, with a signed-in owner session printed at start. It raises the per-minute admission budgets so the seed can be written in a burst; production budgets are unchanged.                                                                                                     | Lets the dashboard be exercised and screenshotted without live services; nothing in it is presented as live data.                                                                |
| BD29 | The briefing preview returns each included item's score and its four components, and the fixed weights (`BRIEFING_WEIGHTS` in core). The agent-facing `check` never returns them.                                                                                                                                                                                                                                                | People need to see why an item was chosen; agents get only the briefing text.                                                                                                    |
| BD30 | Invitations: open ones are listed (invitee, role, state, expiry) and can be revoked; the token is stored hashed, so a link is shown only once at creation. The dashboard link is `/invite/<token>`, which a signed-in person opens to join.                                                                                                                                                                                      | Same rule as other tokens: stored as keyed hashes, shown once.                                                                                                                   |
| BD31 | Public showcase: `GET /v1/public/showcase/:id` answers only for projects whose owner enabled it, with only the ticked sections and only confirmed memories; agent names, activity and tokens are never included; everything else is the same `not_found`. It has its own per-address limit. The per-address limit on `/v1/auth/*` now covers only the endpoints that take no credentials.                                        | A public read must be opt-in, minimal and indistinguishable from a missing project; signed-in dashboard loads must not consume the sign-in budget.                               |
| BD32 | Walrus recall sends a Seal session built by Buiry (`packages/storage/src/seal-session.ts`) with `@mysten/seal` and `@mysten/sui` pinned in `packages/storage` only, not the SDK. The session's one Sui read is injected from the chain gateway. The confinement test and ESLint allow only `@mysten/seal` and `@mysten/sui/keypairs/ed25519` in storage and forbid Sui network clients there.                                    | The SDK exports no session helper; our own code keeps logging, caching and errors under our control. Injecting the read keeps chain access in `packages/chain` (owner decision). |
| BD33 | Work on Sui testnet until everything works end to end; Mainnet is a deliberate cutover at the end (owner). Runs load an explicit profile (`scripts/with-env.ts`, `.env.<profile>`) with no fallback to `.env`; the server and the live demo refuse to start when WALRUS_NETWORK, TATUM_NETWORK, DEMO_NETWORK, the relayer's `/config` network or a project's declared Sui network disagree (an unreadable `/config` only warns). | A Mainnet relayer behind testnet labels went unnoticed (A27); a mixed setup breaks Seal sessions and verification silently.                                                      |
| BD34 | Audit fixes without `--force`: a pnpm override pins body-parser 2.4.0 (inside express 5.3.0's `^2.3.0` range); react-router-dom moves to 7.18.5 (a major, all used APIs unchanged). Dev-only advisories (vitest 2, vite 5) are left for a separate upgrade.                                                                                                                                                                      | Clears every production advisory with the smallest change.                                                                                                                       |
| BD35 | Dependency upgrades take the newest release at least two weeks old, one major at a time with the gate after each, pinned exactly; production advisories are fixed by upgrading or by a narrow pnpm override inside the dependent package's own version range, never with `audit --force`. A dev-only advisory without a fix inside the supported range (minimatch through typescript-eslint) is left and reported.               | Small, reversible steps; overrides outside a dependency's declared range would be guesses.                                                                                       |
