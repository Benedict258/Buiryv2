# Decisions made without asking

| ID  | Decision                                                                                                                                        | Rationale                                                                             |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| BD1 | Root `LICENSE` (MIT, pre-existing) left untouched. Package-level licences follow rule 5.                                                        | Changing the repository licence is the owner's call; flagged in the hand-off summary. |
| BD2 | TypeScript sources are consumed directly across workspace packages via `tsconfig` paths and vitest aliases; `tsup` builds exist for publishing. | Fast iteration, no build step before tests.                                           |
| BD3 | Test database: PGlite (real Postgres semantics incl. row-level security, in-process).                                                           | Lets schema, migrations and RLS be tested without a server.                           |
| BD4 | HTTP framework for API: Hono. Validation: zod.                                                                                                  | Small, typed, runs on node http.                                                      |
| BD5 | Chain module layout: `packages/chain/src/tatum.ts` is the single gateway; transports live in `packages/chain/src/tatum/`.                       | Honours "single gateway file" while keeping transports testable.                      |
| BD6 | Package name scope `@buiry/*`; CLI binary `buiry`.                                                                                              | Matches architecture proposals.                                                       |
| BD7 | Initial confidence/decay/weights use architecture section 9 values verbatim and are exposed as `LearningConfig`.                                | Tunable defaults.                                                                     |
| BD8 | Token estimator: ceil(chars / 4) for prose.                                                                                                     | Deterministic, no tokenizer dependency.                                               |
| BD9 | Auto-promotion counts only helpful reports from sessions other than the creating session (no self-promotion); agent `outdated` reports are treated like `wrong`. | Anti-gaming rule in architecture section 9; `outdated` is in the tool schema but not the score table. |
| BD10 | `main` is protected for merges and confirmed direct writes by non-admins, but agents may write `proposed` memories to it (project setting `allowProposedOnMain`, default true). | Without this the single-branch demo and solo flow cannot work; FR-H1 intent is preserved because proposed memories are low-trust and merges still need an admin. |
| BD11 | Agent tokens can carry a `confirm` scope; such an agent may confirm other agents' memories but never its own. Default agents cannot confirm. | PRD FR-G1 lists a confirm permission; D17 and the anti-gaming rules forbid self-promotion. |
| BD12 | Error code `invalid_input` and `plan_limit` were added to the stable list from architecture section 10. | Validation and plan errors need codes. |
| BD13 | Two idempotency layers: a request-level key (project, branch, type, text, evidence, agent) deduplicates replayed tool calls; the storage-level key (namespace + header + text) deduplicates writes. | The header contains a fresh memory id, so the architecture's storage key alone cannot catch a reconnect replay of the same call. |
| BD14 | Agent REST surface for the MCP server lives under `/v1/agent/*` (project implied by the token). | The documented `/projects/{id}/...` routes are for people and API tokens. |
| BD15 | Chain gateway endpoints (`TATUM_GRPC_ENDPOINT`, `TATUM_JSONRPC_URL`) are env vars with no defaults. | Rule 3: no invented hostnames. |
| BD16 | The write queue table is visible to tenant roles only through a project they own (row-level policy on `project_id`). | write_jobs has no workspace column and is touched inside tenant transactions. |
| BD17 | Write queue completion maps back through a `ref` (the memory event id) on the job. | Lets the worker set blob ids on events and memories without the storage package knowing about memories. |
