## 1. Product in plain words

**What it is.** Buiry is a shared project memory for AI coding agents. Agents connect over MCP (the Model Context Protocol). They:

1. read a short briefing before a task;
2. record what they learn as typed memories with evidence;
3. report whether a memory helped;
4. leave a handoff for the next session or tool.

People review and govern that memory in a dashboard. Memory text is stored on Walrus Memory; chain facts cited as evidence are checked on Sui through Tatum (`README.md`, `docs/03-architecture.md` section 2).

**Who it is for.** Developers who use AI coding agents on a project, alone or in a small team, and the people who must trust what those agents did (`docs/02-prd.md` personas P1 to P5; section 2 below).

**The problem.** Agents forget between sessions. What one agent learned is trapped in that tool. Remembered facts silently go stale, for example a deployment id after a package upgrade. Nobody can audit where a remembered "fact" came from (`docs/02-prd.md` section 2).

**One-sentence promise (input, not final copy).** The project's memory belongs to the project, not to one tool: every agent starts from what the project already knows, including what failed and what has gone stale, and every memory shows where it came from.
